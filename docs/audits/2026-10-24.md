# Audit 2026-10-24

Reviewed commit `007b750`, before the first real run (`--frameworks=vanilla --iterations=1`).
Line numbers refer to that commit. Reviewer: Claude (Opus 5.5), with decisions made by Nolan.

The question was what a skeptical senior engineer would ask before running this on their
own machine: security, needless complexity, duplication, architecture, anything else.

Summary: no blockers. Most findings were minor. The ones that could have changed the
conclusions were about test integrity (#5), broken apps getting performance numbers (#6),
missing values showing as zero (#7), search latency (#10) and token reporting (#11). All
five are fixed. The two security findings (#1, #2) were overstated for a home machine.

Fixes landed in the commit before the one that added this file.

### 1. Credential readable by every process in the agent container

`ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` sits in the container's environment for its
whole life. npm install scripts, `npx` MCP servers and the agent's own app code can read it.

Won't fix. Claude needs the key to run, and anything Claude runs inherits it. The suggested
fix (unset it after `claude` exits) would only have protected the final `npm test`, and #5
moved that test to a container that never gets the credential anyway. The real mitigation
is a key with a spending limit, which the README now says.

### 2. Agent containers have full network access

`--add-host` hides only `pokeapi.co` and `www.pokeapi.co`. With
`--dangerously-skip-permissions`, the agent can reach the LAN, and on a cloud VM the
instance metadata endpoint.

Won't fix. The benchmark runs on a home machine. Blocking `pokeapi.co` is there to stop
the most common way of cheating, not every way. Revisit this before running on a cloud VM
that has an instance role.

### 3. Shared copies of the credentials file break each other

`run.mjs` fell back to `~/.claude/.credentials.json` and gave every container the same
copy. That file holds a refresh token that changes whenever it's used. With `--parallel`,
containers logged each other out.

Fixed, by removing two features. `--parallel` is gone, because we don't need it. Removing
it wasn't enough on its own, since the copy is read once, so even serial containers share
it. If the first container refreshes the token, later ones can fail. So `run.mjs` no longer
reads the file and requires `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` (from
`claude setup-token`). It checks this before creating the run directory.

### 4. A timeout throws away the whole run

`podman stop -t 10` sends SIGTERM to PID 1, which is bash. Bash running as PID 1 ignores
it, so the container gets SIGKILLed 10 seconds later. The run loses its repo tarball, its
final test and the `result` event in the transcript.

Won't fix. If an agent hits the timeout, losing the run is acceptable. One side effect is
worth knowing: a timed-out run shows `—` for tokens and cost, not what it spent.

### 5. The final test could be gamed or contaminated

The agent runs as `agent`, the same user that ran the final test, and that user owned all
of the following:

- `/home/agent/pristine`, the backup copy used to restore the tests.
- `run-agent.sh` itself. Bash reads a script as it runs, so edits take effect mid-run.
- The root `node_modules`, including `@playwright/test`. It wasn't restored.
- `data/`, which wasn't restored either, even though `SPEC.md` says the harness uses its own copy.

A dev server left running on port 3100, or an API on 9100, would answer `waitFor` in
`tests/run.mjs` before the new process failed to bind. The tests would then run against
the leftover process.

Fixed. `run-agent.sh` now only runs the agent and saves the repo. `run.mjs` then copies
`app/`, and nothing else, into a fresh `pokedex-base` container and runs `npm test` there.
The mount is read-only, so the copy on the host stays as the agent left it. `run.mjs`
appends `final_test_exit` to `agent/run-info.txt` after the agent's container has exited,
so it overrides anything the agent wrote there. A simulated run with a fake `podman`
confirmed that a forged `final_test_exit=0` loses. The backup copy in the image and the
restore step are gone. The test container also never receives the credential.

### 6. Apps that fail the tests still get performance numbers

A half-built app that renders an empty page scores well on Lighthouse, and it went into
the medians.

Fixed. `run.mjs` skips measuring an iteration whose final tests failed and writes the
reason to `measure/error.txt`. Its tokens, cost and time still appear in the report.
`--measure-failed` measures it anyway. We chose skipping over measuring and filtering
because it's simpler and saves the measurement time.

### 7. Missing values show as `0` in the report

`fmt(r.mobilePerf * 100)` and `fmt(r.tokens / 1e6, 2)` multiply before the null check, and
`null * 100` is `0` in JavaScript. An unmeasured app showed a performance score of 0, and a
timed-out run showed 0.00 M tokens.

Fixed. `fmt` takes a scale and applies it after the null check. Missing values print as
`—`.

### 8. `--measure-only` overwrites the record of the agent image

`--measure-only` rebuilt all three images, including the agent image with whatever
`latest` meant that day. It then overwrote `config.images`, so an old run claimed its
agents ran in an image they never used. This affected the record only, not the results.

Fixed. `--measure-only` rebuilds only the base and measure images and records them as
`measureOnlyImages`, leaving `images` alone.

### 9. `--claude-version=latest` is cached by Podman

The build argument is always the string `latest`, so Podman reuses the layer from the first
build. "latest" freezes at whatever was current then.

Deferred. `run-info.txt` records the version that actually ran, so nothing is lost. The
fix is to resolve the version with `npm view @anthropic-ai/claude-code version` in
`run.mjs` and pass that to the build.

### 10. Search latency includes about 400 ms of typing

The timer started before typing `char`, and Puppeteer holds each key for 100 ms. Every app
got the same fixed delay added, which squashed the differences between them.

Fixed. The flow types `cha`, starts the clock just before pressing the final `r`, and
stops it when the 7 results show. `cha` matches 18 species, so the wait can't end early.
The input event fires on keydown, so the clock starts at the right moment. The Lighthouse
timespan still covers all four keystrokes, so INP covers all of them too.

### 11. "Total tokens" hides the cache read share

The total adds input, output, cache reads and cache writes. Cache reads are usually most
of it and cost a tenth as much.

Fixed. The report shows total, cache reads, uncached input (input plus cache writes) and
output as separate columns. It still sorts by total tokens. Sorting by cost was suggested
but not discussed.

### 12. `.idea/` makes `harnessDirty` true

`git status --porcelain` lists untracked files, so an IDE folder marks every run as dirty.

Won't fix. It doesn't affect results. `export-template.sh` copies only tracked files
under `template/`, so `.idea/` never reaches a container.

### 13. The measure container doesn't block `pokeapi.co`

Won't fix. It isn't needed. The agent's tests already run with `pokeapi.co` blocked,
and now so does the test container from #5.

### 14. `--strict-mcp-config` probably drops the Svelte plugin's MCP server

Claude Code's help says the flag ignores every MCP configuration other than
`--mcp-config`. The Svelte plugin brings its own server.

Fixed with a guard, since the claim itself isn't verified. `run-agent.sh` leaves the flag
off for `sveltekit`. Every run now records the MCP servers the session actually had, as
`mcp_servers=name:status,...` in `run-info.txt`, taken from the transcript's init event.
The report lists them. The first sveltekit run will show whether the plugin's server
connected.

## Not discussed, still open

Smaller bugs:

- One Lighthouse error on any URL aborts the whole measurement, and `results.json` is only written at the end (`measure.mjs:86`, `:324`).
- If Caddy's root certificate never appears, `stack.mjs:419` carries on. Server-side API calls then fail with TLS errors that look like app bugs. Nothing checks that Caddy itself is ready.
- `num()` in `run.mjs` accepts fractions, so `--iterations=1.5` is allowed.
- `codeStats` runs after the build, so build output the app doesn't gitignore (`dist/`, `.next/`) counts as source lines.
- A corrupt `results.json` crashes the whole report (`report.mjs`, `JSON.parse` without a try).
- `measure.mjs` imports `chrome-launcher` without declaring it. It resolves only because npm hoists it out of `lighthouse`.
- `run.mjs` ignores unknown options, so a typo like `--iteration=3` does nothing and says nothing.

Duplication and cleanup:

- Two hand-written argument parsers (`run.mjs`, `measure.mjs`). In `measure.mjs`, a missing `--runs` falls back to 5 only by accident. `node:util` `parseArgs` would replace both.
- `median` and `round` exist in both `measure.mjs` and `report.mjs`, with different NaN handling. `LH_URLS` in `measure.mjs` repeats paths from `PAGES` in `screenshots.mjs`. The `-\d+$` iteration folder regex appears in `run.mjs` and `report.mjs`.
- `start`, `kill` and `waitFor` are copied between `bench/stack.mjs` and `template/tests/run.mjs`. That's justified, because the template has to stand alone for agents, but a comment should say so.
- `mcp-probe.sh` computes `toolsSha256` twice.
- `deep()` in `measure.mjs` is `evaluateHandle` under another name.
- The root `package.json` is `npm init` boilerplate.
- Stale paths in comments: `export-template.sh` and `frameworks.mjs` refer to `bench/agent/`.

Open questions:

- Were the reference screenshots captured inside `pokedex-measure`? If the host's fonts made them, even the gold app won't score 1.0 on visual match. Measuring gold in the container would give the ceiling, and a gold row in the report would give every number a baseline.
- The live-data check is fully visible to agents (`tests/fixtures/live-data-overlay.json`). A second overlay used only by the final test would catch apps that hardcode Benchmon.
- The API sends `Cache-Control: max-age=86400` (`template/api/server.mjs`), but the tests treat the data as changing between build and start. An app whose HTTP cache survives from build to start would fail for honoring the header. Intended?

## Checked and fine

- The scripted flow handles shadow DOM. I first suspected Puppeteer's `polling: 'mutation'` would miss changes inside shadow roots. Version 25 observes every open shadow root (`injected/Poller.js`).
- Extracting the agent's tarball on the host is safe with GNU tar's defaults. It strips leading `/`, refuses `..` and delays symlinks. Keep using GNU tar.
- Measurement runs one app at a time after all agents finish, so agents don't disturb the numbers.
- The data comes from pinned commits, the Node tarball's checksum is verified, the template is exported from `git ls-files`, and the data download is cached in its own image layer.
